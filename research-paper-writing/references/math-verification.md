# 数学验证工作流

## 建立可核查的主张

1. 写下主张的精确版本，给定对象、类型、定义域、量词、适用设置与可观测量。标注它是恒等式、条件结论、经验主张还是尚待检验的机制。
2. 列出每个假设及使用处，区分由数据设计保证、由定义保证、能直接测量、只能以代理支持、目前未知。说明适用范围和失效表现。检查约束是否可行，分母非零，归一化、边界及初始条件是否有效。
3. 选用最贴切的结论类型。定义用于约定对象，Lemma 用于支撑后续证明，Proposition 用于陈述局部可证明关系，Theorem 留给独立重要且完整证明的结论。没有证明的机制写作假设，经验现象由数据支撑。

## 验证证明及其实现

| 顺序 | 检查 | 最低产出 |
|---|---|---|
| 1 | 先从假设独立推导，再对照原稿和引用。检验是否偷换变量、量词、优化域或总体与样本 | 规范化陈述及符号表 |
| 2 | 每行写明依据、使用的假设和关系方向。检查条件期望与条件独立、交换极限/导数/积分的条件、等价与松弛 | 行号、变换、依据、假设和状态 |
| 3 | 检查一阶条件的角色、凸性或二阶证据、约束和 KKT 前提，区分存在性、最优性、唯一性与收敛性 | 精确的结论和适用范围 |
| 4 | 找反例并做极端值、单位、维度、符号、退化与零值检查。复杂结果可用符号或小规模数值交叉检查 | 可重做的检查及失败条件 |
| 5 | 对照目标、伪代码和实际代码，核对停止梯度、采样分布、估计量、数值保护、停止准则及随机性 | 理想形式到实现的差异与后果 |
| 6 | 用最简单实验检验关键假设、机制预测与替代解释。指标须对应声称解释的量 | 机制、对照、指标、判伪条件和执行状态 |

检查状态用“已独立推导”“有条件成立”“数值检查通过”“发现反例”“待证”或“待核实现”。小规模数值结果只作为交叉检查。先识别算法保证属于哪个对象、哪一步、哪种模式。子问题下降、单次更新改进、总体代理目标最优和全流程收敛是不同主张，需要各自证据。

```text
逐行推导（变换 / 依据 / 适用条件）：
最简反例、退化或边界：
实现对应（代码位置 / 差异）：
可证伪预测（对照 / 指标 / 削弱主张的结果）：

尚缺材料和下一步：
```
